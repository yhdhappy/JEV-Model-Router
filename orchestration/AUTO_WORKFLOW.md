# JEV Model Router 自动多 Agent 工作流

## 目标

本文件定义项目的自动开发闭环。项目负责人不参与开发、审核和返工的中间传递。

唯一总顾问：

- ChatGPT 网页版 GPT-5.6 Sol High
- 通过 WebCodex Mac 读取项目、调用 Paseo CLI、检查结果并决定是否进入下一任务

执行 Agent：

- 开发：Paseo / Codex / GPT-5.6 Luna / High / Auto-review
- 审核：Paseo / Pi / DeepSeek V4.1 Flash / Medium

## 自动流程

总顾问每次启动后必须：

1. 阅读项目目录中的全部产品、技术、状态和实现文档。
2. 读取当前代码、测试与工作流状态。
3. 根据技术验证方案确定唯一的下一个 T-xx 任务。
4. 将该任务直接派给开发 Agent；项目负责人不负责复制粘贴任务。
5. 等待开发完成，收集开发报告、代码变更和测试结果。
6. 将同一任务直接交给审核 Agent 独立审核；项目负责人不负责转交。
7. 审核 FAIL 时：
   - 总顾问判断审核意见是否成立；
   - 成立的问题直接发回原开发 Agent；
   - 等待修复；
   - 再交给审核 Agent 复审；
   - 持续循环，直到审核 PASS 或出现 BLOCKER。
8. 审核 PASS 后，总顾问必须独立检查：
   - 是否满足原始 T-xx 验收条件；
   - 实际代码变更；
   - 实际测试结果；
   - 是否越界修改；
   - 是否违反产品冻结边界。
9. 总顾问认可后：
   - 更新工作流状态；
   - 自动确定并启动下一个 T-xx；
   - 不要求项目负责人手动确认每个任务。
10. 总顾问不认可时：
   - 形成明确修改意见；
   - 自动发回开发 Agent；
   - 重新进入开发 → 审核 → 总顾问验收闭环。

## 只有以下情况才停止并询问项目负责人

- 产品文档与技术方案发生实质冲突；
- 需要修改冻结产品定义；
- 需要新增真实付费、部署、发布或不可逆外部操作；
- 缺少关键凭证或权限；
- 连续返工仍无法满足验收条件；
- 出现无法由现有文档判断的产品选择。

普通代码问题、测试失败、审核 FAIL、返工和复审均不得要求项目负责人手动中转。

## 阶段边界

严格遵守《JEV_Model_Router_产品方案_v0.3_冻结版》和《JEV_Model_Router_技术验证方案_v0.1》。

当前阶段只做 Core + CLI 技术验证：

- 不开发 UI；
- 不接真实 Agent Adapter；
- 不改产品冻结决策；
- 不提前执行后续 T-xx；
- 每次只完成一个 T-xx，通过总顾问验收后自动进入下一个。
